# 05 — Tracker and parent/part ownership

Model 1 was actually loaded on CPU from the local registered checkpoint during this phase. The resulting backend was **IoU fallback** because the optional `lap` package is absent; a warning is emitted and shown by runtime status. Model 1 integrity was `not_checked` in this non-strict load. This does not establish live-camera tracking performance. `requirements-bytetrack.txt` declares the optional dependency, and `FISH_REQUIRE_BYTETRACK=1` refuses fallback when ByteTrack is required. No packages were installed or model weights changed.

Full-frame association uses all detected parent competitors, including unscheduled and finalized/untracked neighbors; uncertain ownership is unassigned or ambiguous rather than given to an arbitrary fish. Duplicate regions for one parent do not both contribute. Crop mode assigns detections inside a selected crop and has different overlap limitations. Tracker IDs remain the responsibility of the tracker; geometry tests cannot establish that physical fish retain IDs during real crossings.

Added a synthetic known-ID crossing and partial-overlap regression in `tests/test_association.py`: assignment before crossing, ambiguity during overlap, and assignment to the original ID after separation. Existing tests cover an absent parent, duplicate detections and tracker IDs, unscheduled parents, dropout/reentry, and independent grades for two fish with different Tail availability. Command: `python -B -m pytest -q -p no:cacheprovider tests/test_association.py tests/test_tracker_backend_qa.py tests/test_runtime_diagnostics.py tests/test_tail_optional_policy.py --tb=short`: **50 passed, 44 subtests passed** (`05_association.log`). Local model load evidence: `05_tracker_loaded.log`. No real annotated overlap video was available; real tracking, ownership and a visual validation case remain pending.
