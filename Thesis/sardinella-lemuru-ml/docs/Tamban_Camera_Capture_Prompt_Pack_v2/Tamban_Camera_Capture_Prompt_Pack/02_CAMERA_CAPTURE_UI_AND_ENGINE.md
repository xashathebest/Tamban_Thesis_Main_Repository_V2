# Prompt 02 — Camera Capture sidebar / collection engine

Execute only after baseline approval. Preserve grading logic, training data, checkpoints and existing pages. **Data gathering is its own entity; DO NOT modify any existing Live Inspection camera usage, controls, routes, lifecycle, or configuration.** Add an accessible responsive `Camera Capture` button to `frontend/index.html` sidebar and `view-capture` page. Register `viewMeta.capture` and minimal navigation hooks in `frontend/app.js`; use existing CSS design tokens. Implement a separate `frontend/capture.js` and NEW backend capture router/service with dedicated camera handle/state/session. No refactor or edits to `src/api/camera.py`, `src/api/raw_preview.py`, or existing inspection endpoints. Shared app files may receive ONLY the minimal additive sidebar/nav and new router mounting, never modifications to existing camera functions.

Crucial: existing `CameraInspectionService` owns the inspection camera and is **read-only** to this task. Create an independently owned capture-only acquisition path; do not introduce or retrofit shared leases inside inspection. Never attempt a second `cv2.VideoCapture` on the same occupied device: check/refuse where possible and safely handle operating-system busy errors. If inspection uses that physical camera, show an explicit conflict and ask the operator to stop inspection manually (or select another device); NEVER stop/restart/change inspection itself. A capture-only session must work without model checkpoints using its own startup path; never start or modify inspection for photos. If a reliable guarantee requires editing inspection code, STOP and seek approval. Implement start/stop and explicit mode conflict 409, safe release on error/disconnect and no stale frames after restart. Capture original camera frames, not the annotated inference stream or preview MJPEG.

Controls: device selection; live raw preview; a **large, clearly labeled `Capture Photo` button**, available in a manual-only collection session with no automatic run and NO countdown. Each click must acquire exactly one fresh non-overlay frame, save one original local file, and enqueue it for Drive using the shared capture-only save/manifest pipeline; tag `capture_mode=manual`. The same independent camera reader serves manual and automatic shots; serialize them to avoid duplicate/stale frames and extra device handles. Allow safe manual shots during automatic collection while maintaining distinct IDs and frame freshness. If the camera is busy/closed, disable the button and explain why. Then provide countdown 0/5/10 seconds; once countdown completes, 1 image **each second** by default (adjustable 1/2/5 seconds); separate timed-burst duration 5/10/30/60 seconds or unlimited until Stop; optional target count 10/25/50/100/custom; Pause/Resume/Stop. Show run state, countdown, scheduled vs captured, next shot, late/skipped shots, capture-only FPS and actual camera readbacks. Use server-side monotonic scheduling, no duplicate older frame, bounded queue/storage; log missed deadlines instead of backfilling. Distinguish 5/10s countdown from 5/10s capture duration.

Add one-click manual save feedback (`Saved locally` + thumbnail/file name + Drive sync state), a manual photo counter and optional spacebar shortcut (not while typing). Include editable session metadata fields, grade as *provisional* A/B/C/Rejected/Unknown/Background/Hard negative, photo gallery + full resolution viewer, quality flags, include/exclude for training (non-destructive), notes, keyboard shortcuts and instructions. Focus grid/guide is **preview-only**, never burnt into original. Offer ZIP + manifest download. Preserve raw file and original dataset and protect personal/vendor information. Synthetic tests required; hardware tests must be explicitly reported as done or not done.
