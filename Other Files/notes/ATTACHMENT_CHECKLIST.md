# Attachment and presentation checklist

Use the structure below for your own meeting folder. An attachment is not evidence until it actually exists and is accurately labeled.

| ID | File or folder | Check |
|---|---|---|
| A01 | QUICK_BRIEF and consultation guide | [ ] Readable on the presentation laptop |
| A02 | ZIP/model/configuration identity | [ ] Hashes/version match the demonstrated build |
| A03 | Normal and difficult application examples | [ ] Original image, output and run context retained |
| A04 | Ready_To_Show_Evidence or new notebook outputs | [ ] Recalculated/synthetic/exploratory labels preserved |
| A05 | Actual local runtime log and hardware sheet | [ ] Measured on intended computer; otherwise marked not measured |
| A06 | Expert consultation clips and evidence_index.csv | [ ] Consent scope verified; original files retained |
| A07 | Current QA logs and known limitations | [ ] Old results not relabeled as current |
| A08 | Decision log | [ ] Owner/date/status fields ready |

## Recording clip format
**Title:** Body-part importance informing proposed grading weights.
**Original:** real original filename, unchanged.
**Range:** actual start and end timestamps.
**Supports:** the expert's stated relative importance or actual numerical decision.
**Does not support:** weights or accuracy results that the expert never stated or that have not been tested.
**Status:** proposed / domain-confirmed / experimentally evaluated, as applicable.

Do not invent timestamps, signatures or approval. Include the question and relevant context. A title saying "50/30/20 approved" is inappropriate when the expert only described the body as most important.

## Suggested message
Good afternoon, Ma'am. Attached are our consultation brief, current grading-policy summary, and supporting evidence. We would appreciate your guidance on two-part eligibility, missing-head/tail handling, validation of the proposed weights and features, and our performance targets. We have marked implemented, proposed and pending-validation items separately. Thank you!

## Final practical checks
[ ] All local files and clips open without internet.
[ ] The demo has an image-upload or recorded fallback.
[ ] Private consent forms and original consultation recordings are not in a public repository.
[ ] The actual source/model version being demonstrated is recorded.
[ ] No unsupported accuracy or speed improvement is presented.
