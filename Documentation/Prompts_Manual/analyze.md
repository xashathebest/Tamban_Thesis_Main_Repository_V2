# Codex Task: Fix Model 2 Inference and Ungraded Fish in Analyze Image

## Problem

The Live Inspection / Analyze Image feature fails to grade fish correctly, even when the input is an image from the training dataset.

Observed behavior:
- Model 1 detects two fish.
- Bounding boxes appear around both fish.
- Fish found = 2.
- Class A = 0.
- Class B = 0.
- Class C = 0.
- Rejected = 0.
- Ungraded = 2.
- The interface reports M1 / M2 Ready / Ready.

The application therefore detects fish but does not produce a final grade. Model readiness must not be treated as proof that inference and grading succeeded.

## Primary objective

Find and fix the actual root cause. Do not simply lower confidence thresholds, force a grade, or retrain the models without evidence.

### 1. Trace the entire Analyze Image pipeline

Follow the real execution path from image upload to the final displayed grade.

Verify:
- The uploaded image reaches the intended analysis function.
- The correct Model 1 weights are loaded.
- The correct Model 2 weights are loaded.
- Model 1 detections are passed to Model 2.
- Each fish crop is generated from the correct coordinates.
- Crop padding, image dimensions, color channels, and resizing are correct.
- Model 2 predictions are preserved and passed to the grading engine.
- Predictions are associated with the correct fish.
- The grading engine receives valid part and defect evidence.
- Final grades and diagnostic reasons reach the UI.

Identify every point where valid predictions can be discarded, ignored, or incorrectly converted into an Ungraded result.

### 2. Test both models independently

Using the exact uploaded training image:

**Model 1**
- Print the checkpoint path and model task.
- Print the actual class-name mapping.
- Print every detection's class ID, class name, confidence, and coordinates.
- Save an annotated prediction image.

**Model 2**
- Run inference directly on the original image.
- Run inference on the actual fish crops generated by the application.
- Print the checkpoint path, model task, class-name mapping, and configured inference settings.
- Print every predicted class, confidence, bounding box, and segmentation mask availability.
- Report the number of detections before and after confidence filtering.
- Save annotated images of the actual crops and their predictions.

Do not assume that a model is functioning simply because its weights load successfully.

### 3. Verify class mappings

Compare the actual Model 2 checkpoint class names against the application's expected labels:

- Grade_C_Body
- Grade_A_Body
- Grade_B_Tail
- Grade_A_Tail
- Grade_C_Tail
- Grade_C_Head
- Rejected_Body
- Grade_A_Head
- Grade_B_Body
- Rejected_Tail
- Grade_B_Head
- Rejected_Head

Use the real checkpoint metadata and dataset configuration as the source of truth. Do not silently remap IDs or assume the list order is correct.

If mappings disagree, correct the mapping explicitly and add tests.

### 4. Fix crop generation and coordinate handling

Check for:
- Incorrect XYXY versus XYWH coordinate interpretation.
- Incorrect conversion between normalized and pixel coordinates.
- Crops extending outside image boundaries.
- Crops that exclude fish body, head, or tail.
- Incorrect ROI padding.
- Resizing or color-channel inconsistencies.
- Empty or nearly empty crops.
- Incorrect transformation of segmentation masks back into crop or image coordinates.

Account for partially visible fish. Do not invent missing body parts or treat an invisible part as confirmed defective.

### 5. Fix part-to-fish association

Inspect how Model 2 predictions are assigned to Model 1 fish.

Verify that:
- Each valid part prediction is assigned to the correct fish.
- Coordinate systems are consistent.
- ROI and overlap constraints do not reject valid parts.
- Duplicate suppression does not discard distinct valid parts.
- Predictions are not accidentally assigned to another fish or frame.
- The single Head / Body / Tail per fish-per-frame safeguard preserves the best valid prediction and records rejected duplicates diagnostically.

Add regression tests using synthetic boxes and known coordinates.

### 6. Diagnose the grading engine

Trace the exact conditions that result in Class A, B, C, Rejected, and Ungraded.

For every fish, report:
- Model 1 detection status.
- Model 2 inference status.
- Detected head, body, and tail labels.
- Confidence per part.
- Crack and yellow-defect evidence, if available.
- Missing required evidence.
- Every grading rule that passed or failed.
- The final grade and a specific reason.

Do not silently convert all exceptions, empty predictions, or missing features into Ungraded.

Preserve conservative grading. Never force Class A merely because no defect was detected, and never interpret missing evidence as proof of a defect.

If evidence is insufficient, retain Ungraded with an explicit explanation.

### 7. Add a diagnostic mode to Analyze Image

Add an optional developer diagnostic mode that saves a report for each analysis containing:

- Input image dimensions and file hash.
- Model checkpoint paths and class mappings.
- Inference parameters and elapsed time.
- Model 1 raw and filtered predictions.
- Each generated fish crop and its coordinates.
- Model 2 raw and filtered predictions.
- Part-association results.
- Grading inputs, rule decisions, and final output.
- Exceptions and rejected predictions.

Ensure diagnostics are accessible from logs or a downloadable JSON report. Avoid exposing sensitive filesystem information in the normal production UI.

### 8. Add regression tests

Create tests for:
1. A training image that previously resulted in Ungraded.
2. Model 1 detecting fish while Model 2 returns no parts.
3. Model 2 detecting valid parts but association failing.
4. Incorrect class mappings.
5. Crops with incorrect dimensions or coordinates.
6. Partially visible fish.
7. Missing head, body, or tail evidence.
8. Defect evidence unavailable versus defects positively detected.
9. A valid fish receiving a supported grade.
10. A genuinely ambiguous fish remaining Ungraded with an explanation.

Use actual local checkpoints for integration tests when available. Keep model-free unit tests runnable without downloading weights.

### 9. Constraints

- Inspect the existing implementation and project limitation documents before modifying code.
- Preserve the intended two-model architecture.
- Do not introduce a replacement grading system.
- Do not hardcode expected predictions for the test image.
- Do not fabricate predictions or grades.
- Do not weaken grading requirements just to eliminate Ungraded results.
- Do not change trained weights unless testing proves retraining is necessary.
- Keep production and research-only functionality separated.
- Remove no files unless their usage has been verified.

### 10. Final deliverables

Provide:
- The confirmed root cause of the failure.
- The files and functions modified.
- Before-and-after diagnostic results for the problematic image.
- Model 1 and Model 2 raw prediction results.
- The reason each fish was previously Ungraded.
- Regression test results.
- Remaining limitations.

Do not claim the problem is fixed unless the original failing workflow passes the regression test.
